# Database Contract — Jordan Real Estate Intelligence Platform

**Status:** v1 (frozen) · **Engine:** SQLite (SpatiaLite optional) · **DB file:** `db/jordan_re.sqlite`
**Authority:** `MASTER-PLAN.md` §3 + `K-PACKET.md` §5. This document is the interface other
engineers (scrapers, feature engineering, decision engine, frontend) build against.

If the schema and this document ever disagree, **`db/schema.sql` wins** — it is the single source
of truth. The loader (`db/load_csv.py`) reads its rules (enums, required columns, types) back out
of the live schema, so there is no second copy of the rules to drift.

---

## 1. Universal rules (every collected table)

Every collected table carries, in addition to its own columns:

- **Universal columns:** `evidence_category`, `language`
- **Provenance columns:** `source_name`, `source_url`, `capture_date`, `collected_by`, `confidence`, `notes`

Plus a machine-managed `created_at` (ISO timestamp, defaulted — never supplied in a CSV).

### Shared enums

| Column | Allowed values |
|--------|----------------|
| `evidence_category` | `market`, `government`, `gis`, `infrastructure`, `macro`, `portal`, `builder`, `news`, `derived`, `unknown` |
| `language` | `en`, `ar`, `mixed`, `unknown` |
| `confidence` | `H`, `M`, `L`, `unknown` |

`confidence` at collection time = **trust in the SOURCE only** (official gov = `H`, established
news = `H`/`M`, blog/social = `L`). Whether a fact moves price, and by how much, is computed later
by the Evidence Engine — never mixed into this column.

### The `unknown` vs blank rule (enforced by the loader)

- **`unknown` is the only legal null-object.** Where a collector cannot determine a categorical
  value, they write `unknown`, never leave it blank.
- **Blank in a required or enum column → the row is rejected** and the reason is logged.
- **Provenance is the product:** `source_name`, `source_url`, `capture_date` must be present and
  must not be blank or `unknown`, or the row is rejected.
- Numeric / date columns: `unknown` or blank → stored as `NULL`; a malformed value → row rejected.
- Dates are ISO-8601 `YYYY-MM-DD` text (SQLite has no native date type).

## 2. Tables

Legend: **PK** primary key · *derived* = generated by the DB, never inserted · req = must be non-blank in the CSV.

### `listings` — sale/rent asking-price records (Bayut, OpenSooq, Homes-Jordan, FB)

CSV header order (matches `K-PACKET.md` Dataset 4 — note: **no `price_per_m2`**, it is derived):

`listing_id, portal, listing_url, listing_type, property_type, neighborhood, district, lat, lng, price_jd, area_m2, bedrooms, bathrooms, floor_level, total_floors, view, parking, building_age_years, furnishing, elevator, finish_quality, seller_type, listing_date, main_image_url, description_raw, evidence_category, language, source_name, source_url, capture_date, collected_by, confidence, notes`

| Column | Type | Notes / enum |
|--------|------|--------------|
| `listing_id` | TEXT **PK** | stable per-portal id |
| `portal` | TEXT req | e.g. `bayut`, `opensooq`, `homes-jordan`, `facebook` |
| `listing_url` | TEXT req | |
| `listing_type` | TEXT req | `sale`, `rent`, `unknown` |
| `property_type` | TEXT req | `apartment`, `villa`, `land`, `commercial`, `unknown` |
| `neighborhood` | TEXT req | one of the 5 target submarkets |
| `district` | TEXT | |
| `lat`, `lng` | REAL | decimal degrees; `unknown`→NULL |
| `price_jd` | REAL | JOD as published; no conversion |
| `area_m2` | REAL | |
| `price_per_m2` | REAL *derived* | `price_jd / area_m2` when both present and area > 0 |
| `bedrooms`, `bathrooms`, `floor_level`, `total_floors`, `building_age_years` | INTEGER | `unknown`→NULL |
| `view` | TEXT | `none`, `sea`, `city`, `garden`, `mountain`, `panoramic`, `unknown` |

### `projects` — competitor new-launch developments

`project_id (PK), name (req), developer, builder_tier, neighborhood (req), lat, lng, status (req), unit_types, launch_price_jd_m2, payment_plan, launch_date, units_total` + universal + provenance

- `builder_tier`: `local`, `premium`, `luxury`, `unknown`
- `status`: `planned`, `construction`, `selling`, `delivered`, `unknown`

### `poi` — points of interest (OSM + junior verification)

`poi_id (PK), category (req), name (req), lat, lng, neighborhood, exists` + universal + provenance

- `category`: `school`, `hospital`, `mall`, `mosque`, `park`, `university`, `transport`, `unknown`
- `exists`: `yes`, `no`, `unknown` (junior verification flag; the column is quoted `"exists"` in SQL)

### `districts` — neighborhood / admin boundary polygons

`district_id (PK), name (req), neighborhood, zone_class, far, max_height_m, geometry_geojson, centroid_lat, centroid_lng` + universal + provenance

Geometry is stored as **GeoJSON text** in `geometry_geojson` (SpatiaLite-free fallback). `centroid_lat`/`centroid_lng` give a cheap point for mapping and haversine distance.

### `zoning_plots` — plot-level land-use / zoning polygons

`plot_id (PK), zone_class, far, max_height_m, land_use, neighborhood, district, geometry_geojson, centroid_lat, centroid_lng` + universal + provenance

### `macro_series` — official time series (CBJ index, DLS volumes, DoS permits)

`macro_id (PK, auto), indicator (req), geography (req), period (req), value, unit` + universal + provenance
Unique on `(indicator, geography, period)` — re-loading the same series is idempotent.

### `evidence_items` — Future-Signals pipeline (infrastructure / policy / news)

`evidence_id (PK), type (req), title (req), summary_2_lines, impact_area, expected_year, expected_effect, published_date` + universal + provenance

- `type`: `infrastructure`, `policy`, `market_news`, `unknown`
- `expected_effect`: **only what the source itself explicitly states**, else `unknown`. Interpretation happens in the Evidence Engine, never at collection.

### `neighborhood_profiles` — researched neighborhood context (P2)

`profile_id (PK, auto), neighborhood (req), luxury_level, primary_buyer_type, typical_property_type, typical_price_range_jd_m2, reputation_summary, commercial_mix, population_character` + universal + provenance

- `luxury_level`: `budget`, `mid`, `upper-mid`, `premium`, `luxury`, `unknown`

### `cost_benchmarks` — construction cost per m² by finishing class (cost-approach floor)

`benchmark_id (PK, auto), spec_class (req), cost_jd_per_m2_low, cost_jd_per_m2_high, year` + universal + provenance

- `spec_class`: `basic`, `standard`, `high`, `luxury`, `unknown`

## 3. Engine-output tables (written by the Decision Engine, never collected)

### `derived_premiums` — the Adjustment Engine's derived attribute premiums

**HARD RULE (`MASTER-PLAN.md` §2d-2): premiums are DERIVED from current market data and
recomputed — never hardcoded constants anywhere in the codebase.** This table is where they live.

`premium_id (PK, auto), factor, neighborhood, property_type, derived_premium, method, source, confidence, sample_size, computed_date, notes`

- `derived_premium` is a **fraction**: `0.08` means +8%.
- `method` documents how it was derived, e.g. `paired listing comparison (n=14)`.
- Unique on `(factor, neighborhood, property_type, computed_date)` — keeps a recompute history.

### `recommendations` — persisted Decision-Engine output

`recommendation_id (PK, auto), location_id, neighborhood, property_type, min_safe_price_jd_m2, recommended_price_jd_m2, premium_price_jd_m2, confidence_label, confidence_numeric, narrative, evidence_objects_json, comparables_json, risk_factors_json, alternative_scenarios_json, computed_date, created_at`

Scalar outputs are first-class columns; the nested arrays are stored as JSON text in the `*_json`
columns following the `RecommendationResult` contract below.

## 4. `RecommendationResult` JSON contract (Decision Engine → frontend)

The engine emits this object per priced location; scalars map to `recommendations` columns and the
nested arrays are persisted in the matching `*_json` columns.

```json
{
  "location_id": "prj-abdoun-terraces",
  "neighborhood": "Abdoun",
  "min_safe_price_jd_m2": 980,
  "recommended_price_jd_m2": 1085,
  "premium_price_jd_m2": 1190,
  "confidence": { "label": "H", "numeric": 0.82 },
  "evidence_objects": [
    {
      "factor": "Sea/City View",
      "adjustment": "+8%",
      "confidence": "High",
      "method": "paired listing comparison (n=14)",
      "datasets": ["listings"],
      "sources": [
        { "name": "Bayut", "url": "https://www.bayut.jo/...", "capture_date": "2026-07-08" }
      ],
      "category": "current_state",
      "explanation": "Comparable units with a view list 8% higher than matched units without, same building band."
    }
  ],
  "comparables": [
    {
      "listing_id": "BYT-001",
      "neighborhood": "Abdoun",
      "price_per_m2": 925.0,
      "similarity": 0.91,
      "adjustments_applied": ["view", "floor"]
    }
  ],
  "risk_factors": [
    { "factor": "Thin comparable set", "severity": "medium", "detail": "Only 6 sale comps within 800m." }
  ],
  "alternative_scenarios": [
    { "name": "Conservative launch", "recommended_price_jd_m2": 1040, "rationale": "..." }
  ],
  "narrative": "Recommended launch band 980–1190 JD/m² for Abdoun apartments..."
}
```

Field notes:
- `confidence.label` ∈ `H` | `M` | `L`; `confidence.numeric` ∈ `[0, 1]`.
- Each `evidence_object` renders as one row of the adjustment-grid waterfall with source chips.
- `evidence_object.category` ∈ `current_state` | `future_signal` (the two pipelines, never mixed).
- Every `evidence_object` must carry at least one `sources[]` entry — nothing appears in the UI without provenance.

## 5. Loading data

```bash
python db/init_db.py                          # create/upgrade db/jordan_re.sqlite (idempotent)
python db/load_csv.py path/to/file.csv        # table auto-detected from the header
python db/load_csv.py path/to/file.csv --table listings --replace
```

Every load writes `data/processed/load_report_<table>.txt` listing rows read / inserted /
duplicates / rejected, with a per-row reason for every rejection.
